# Enhancement engine status

This document distinguishes implemented library capabilities from application integration and verified runtime behavior. Presence of code does not imply production validation.

## Implemented on `feat/safe-enhancement-engine`

- Deterministic report/financial themes; header fill/font/alignment/border; readable body fonts; data-type alignment; subtle row separators; optional banding; bounded content-based widths; structured change records; deep style merging that fills missing properties without replacing existing explicit style leaves.
- Read-only number-format proposals for dates, currencies, percentages, integers and decimals. Explicit repair is opt-in, confidence-thresholded, and changes number-format metadata only; it never coerces cell values. Currency and percentage conventions remain ambiguous without caller-provided business configuration.
- Read-only data-quality profiling for mixed types, numeric-looking text, suspicious date years, impossible calendar dates, leading/trailing whitespace, full-width compatibility characters, Excel error values, negative quantity-like values, possible duplicate rows and configured missing keys. Findings are never automatically applied.
- Review-first structural formula-repair proposals based on nearby formula-template consensus. The library does **not** infer business meaning, units, accounting rules, or intended formulas. Applying a proposal requires explicit opt-in and a confidence threshold.
- Guarded recovery snapshots capture the complete normalized model, are persisted under the configured application data directory with database file metadata and SHA-256 checksums, and reject undo when the current model differs from the recorded post-repair state. Atomic undo claims prevent duplicate restores. Deployment still needs persistent-volume backups, retention rules and authorization.
- Bounded in-memory batch orchestration with file-count/size/concurrency limits, safe relative paths, duplicate-name rejection, input-buffer isolation, stable result ordering and per-file failures. A server-only directory adapter recursively processes supported workbook files under a selected root, checks depth/file/byte budgets before reading, skips symlinks and never writes to the source tree. The analysis upload UI supports selecting a folder and processing its workbook files as a bounded batch of up to 12 files; recursive server-filesystem traversal remains a server-only library API.
- Offline XLSX export/reopen checks compare worksheet count/order/names/visibility/dimensions, formulas and locations, non-formula values/types, explicit style properties and number formats, row/column layout, merged ranges and feature markers. Native Excel recalculation checks protected OOXML package-part presence plus structural marker counts for feature-bearing worksheet, drawing, chart, pivot, external-link, connection and workbook XML. A regression test confirms a real hyperlink missing from the output package is rejected. These are conservative structural checks, not proof of visual parity, formula equivalence, or preservation of every unsupported OOXML feature.
- LibreOffice Calc adapter for isolated-copy recalculation when `soffice` is installed. LibreOffice is not Microsoft Excel and may calculate proprietary functions differently.
- Native Microsoft Excel COM adapter for Windows hosts with installed/licensed desktop Excel. It opens a disposable copy with macros disabled and external-link updates suppressed, forces a full dependency rebuild, saves in the original XLSX/XLSM format, and checks worksheet/formula structure and feature markers. It does not guarantee identical outcomes for every add-in, external data source, macro-driven workbook, or third-party Excel extension.
- OOXML inspection detects advanced features through package-part names, worksheet/workbook XML markers, relationship types, and content-type declarations. The reduced-model serializer treats detected features as unsupported and blocks destructive XLSX export. This is a conservative preflight, not a full OOXML schema validator. Digital-signature parts and signature content types are detected; signed workbooks are blocked from recalculation because saving changes can invalidate signatures.
- Regression tests cover formatting, data-quality, number-format proposals, formula proposals, recovery, batch orchestration, semantic-header false positives, package-part checks, local round-trip verification, hyperlink-loss detection, relationship-aware OOXML feature detection, bounded retry policy, and database lease fencing. A manual LibreOffice and Windows Excel COM smoke script has been added; CI now installs LibreOffice Calc and runs a real formula recalculation smoke test. The full Linux CI workflow passed at commit `eb43a1d` (type-check, lint, unit tests including bounded retry-policy tests and hyperlink-loss detection, XLSX download integration, production build, production access gate and end-to-end upload → preview → apply → exports → download). Windows Excel COM and installed LibreOffice runtime behavior are not exercised by the Linux CI workflow. Windows Excel COM and installed LibreOffice runtime behavior are not exercised by the Linux CI workflow.

## Not yet production-complete

- Business-aware formula repair still needs explicit domain rules, named input semantics, unit/currency checks, formula result comparison, and human approval. Structural similarity is not proof of correctness.
- Full OOXML preservation across charts, pivot tables/caches, macros, hyperlinks, validation, conditional formatting, drawings, embedded objects, connections, slicers, controls, signatures and vendor extensions is not guaranteed by the reduced model serializer. Existing serializer preflight must continue to fail closed on unsupported features.
- The enhancement profile/preview/apply/undo and recalculation API is wired into `POST /api/analysis/:id/enhancement` and surfaced in the Analysis Detail **Enhancement Engine** tab. Apply writes verified copies and persistent recovery snapshots; undo refuses to overwrite a later model state. Native recalculation writes separate copies and leaves the current analysis model and source uploads unchanged. The app has a shared Basic Auth gate, but there is no per-user identity/ownership or tenant model and no distributed rate limiter. Do not expose it as a multi-tenant service or to untrusted networks until those controls are implemented and reviewed. Runtime-specific integration tests remain outstanding.
- Enhancement recalculation still runs synchronously in the API request and requires the selected runtime to be installed/configured. The general analysis/export worker now tracks attempt counts and bounds stale-job recovery to three total claims, then marks exhausted work failed. This is not yet a complete fencing-token lease design: a worker paused beyond the stale threshold could resume after another worker reclaims the job. Long-running cancellation, resumability and strong lease ownership checks remain outstanding.
- Recovery snapshots are persisted and connected to the undo endpoint. Crash recovery depends on durable storage for both PostgreSQL and `XRAY_DATA_DIR`; backup restoration, retention and multi-user authorization policies still need deployment-level validation.
- Batch orchestration is bounded and in-memory, with a folder picker capped at 12 supported files and per-file skip reasons. Recursive server-filesystem traversal exists as a server-only library adapter, not a user-selectable server path. Zip packaging, resumable jobs, durable queues, cancellation, rate limiting and large-volume load testing remain outstanding.
- Offline verification does not yet compare rendered workbook screenshots, recalculated values against a trusted oracle, pivot/cache refresh outcomes, chart rendering or every OOXML package part.
- Enterprise-grade validation still needs a broad real-workbook fixture corpus, fuzzing, security testing, performance/memory benchmarks, rendered visual comparisons, Windows Excel COM CI and LibreOffice CI.

## Safety invariants

1. Never mutate the source file in place; work on disposable copies.
2. Never auto-apply ambiguous data-quality or semantic-format findings.
3. Never claim Microsoft Excel parity from LibreOffice results.
4. Never reconstruct unsupported OOXML features through the reduced model serializer; fail closed.
5. Never silently remove VBA or invalidate digital signatures.
6. Keep all work on `feat/safe-enhancement-engine` until the repository owner reviews and merges it. Tracking issues remain open.
